## 当前能测试的功能：F5 诊断快照

1. 从原快捷方式启动游戏，到一个稳定、可重复进入的位置。
2. 按一次 F5（Shift+F5 也可），等待写盘完成。
3. 检查 `E:\CodexProjects\DeadSpaceLegacy\run-host\Runtime-PC` 中新出现的
   `state-<时间戳>-f<帧号>.dsstate`。若设置了 `TOUCHHLE_DS_STATE_DIR`，以该目录为准。
4. 在同一运行目录的 `touchHLE_log.txt` 中确认 `[DSstate] saved`，核对文件路径。
   这只验收“诊断快照写入成功”，不能验收“存档可以恢复”。

F9/Shift+F9 是已有缺陷的旧恢复入口：它没有恢复其他线程、宿主 GL/音频等
完整状态，已有输入失效/崩溃记录。不要在准备好的 Boss 复现现场按 F9。
本轮没有修改 F5/F9 实现，未提供即时存档恢复测试版本。

它不会强制游戏存档。新开一次归档目录不代表保存了当前场景；必须核对
`*_CheckpointSave.sb` 的哈希和内部关卡 ID。

本次后台仅捕获旧的 `01_gov_01` 检查点，没有捕获第 12 章/Boss 进度。
不要用这份备份试图返回本次 Boss 前的位置。

## 真正即时/手动存档的后续验收标准（尚不能执行）

待原生序列化保存、独立备份及一致恢复入口实现后，才做以下验收：

1. Boss 前保存 A，记录位置、血量、弹药、关卡和战斗阶段。
2. 走动并改变血量/弹药，然后恢复 A；核对状态且操作/暂停正常。
3. 完全退出并重新启动后再次恢复 A，证明恢复不依赖旧进程内存。
4. Boss 战后保存 B；分别恢复 A/B，核对 Boss/触发器状态且可继续推进。
