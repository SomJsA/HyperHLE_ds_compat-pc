## Opening regression and native projection boundary

The high-tier GLES2 prologue lost distant station and asteroid geometry. Same-binary PC A/B identified the missing finite-far correction: turning off depth testing does not bypass homogeneous vertex clipping. The GLES1 path already had this opening projection repair.

The shader renderer receives its pure projection at `ShaderRendererAPI::SetProjection` (original address `0x5675e0`). The entire original 140-byte function and exported ARM symbol must match before replacing the projection store at `0x56763c` with a handled trap. Only a finite, pure perspective matrix matching the accepted opening z-row/near coefficient receives stored `m[10] = -1`; the source const-reference and x/y/near coefficient remain unchanged. All GPRs, CPSR and FPSCR are preserved, and execution continues at the next original instruction. Unknown code, off-center/transformed/orthographic and other projection ranges remain unchanged. `TOUCHHLE_DS_ES2_PROJ_FIX=0`, the existing `TOUCHHLE_DS_NO_PROJ_Z_FIX`, or `TOUCHHLE_DS_PROJ_Z_INFINITE=0` preserve the original diagnostic path. The repair is bundle-specific and adds no files or markers to game data.

A verified original shader fragment also guards its disabled zero fog range, and the old content-key NO_FOG rules apply through context/sharegroup-owned texture identity with a scoped uniform restored after each selected draw. Unknown programs/resources remain untouched. Android GLES2 depth attachment promotion now follows the existing guarded D16-to-D24 policy, preserving capability and D16 fallback. These fixes alone did not remove the main black occlusion; the projection A/B provides that causal evidence. Fog probes are explicit, bounded and default off.

Validation separates source/function fingerprints, actual ARM store replay with register/flag/source checks, real backend GPU pixels, same-library opening A/B, normal package builds and isolated device cleanup. A camera sample is not a performance result, and a normal corridor does not prove the prologue.
