# PC独立屏幕匹配（2026-11-03，用户明确修订）

此规则替代e2093b05的最小整数档算法。PC读取物理主屏像素，1080P取4×（1920×1280）、1440P取6×（2880×1920）、2160P取8×（3840×2560）。游戏横屏底分480×320，其他高度向上取偶数底分倍率=2*ceil(屏幕高度/640)。Windows DPI逻辑坐标不参与；每次启动游戏前通过EnumDisplaySettings重新识别，当前页面也立即刷新。输出尺寸独立可选，已识别物理屏幕优先；无法识别物理屏幕时仅用明确输出高度作可见回退，否则提示选择输出。

内部渲染、输出分辨率都在基础显示区展示，可见当前内部→输出和参考屏幕高度；内部渲染下拉框移出高级画质区域。画质档位、硬件画质建议均不再改动内部倍率。新配置默认屏幕匹配，PC纹理4×、MSAA4×、AF4×；原有显式纹理/采样/手动倍率仍保留，质量调整只改采样/过滤/后处理。屏幕比例保持3:2与既有viewport留边，不拉伸。

稳定自动标签“屏幕匹配（启动时识别）”保存策略而非本次倍率。诊断host.json写明自动/手动、物理参考高度、规则与请求内部尺寸；startup的实际分配为准。此项不修改Android、IPA、存档布局或游戏时钟，不宣称稳60FPS。原生库与启动器分别记录构建提交、SHA与匹配的源码映射。
