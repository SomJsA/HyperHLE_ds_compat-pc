# 可选存档节点采集器：代码准备

2026-10-31，Asia/Hong_Kong。分支 `codex/save-structure-20261031`。

用户最后约束为“先准备代码，会作为一个可选开关”。本轮只修改源码、执行离线测试和构建。
**未安装到平板、未开启实际游戏监控、未启动一周目试玩。**

## 开关与使用流程

Android 启动器“存档与文件”中新增“自动采集存档节点（可选）”，**默认 false**，下次启动
游戏生效。主开关关闭时，不创建采集器、注册 FileObserver、创建节点库或拍摄节点画面。
“附带节点画面”是主开关下的选项；单独勾选它不会启动采集。

开启后，正常游玩即可累积节点。可填写本轮名称区分试玩者/周目；暂停菜单提供
“标记最近一次游戏存档”，输入人类可读标签。标签指向已经落盘的游戏存档，不产生新的任意位置存档。
游戏退出完成后可在启动器导出节点库 ZIP。

独立测试包的游戏目录沿用内部 `files/save-lab/.../Documents`；节点库另存为
`files/save-node-bank`，位于被观察的 Documents 外。普通包的数据根选择沿用原有规则。
本轮准备了 Android 开关与可复用归档/解析核心；PC 启动器尚未接入该开关。

## 归档内容与行为

- Documents/var 和 Documents 的 SBIN 文件完成写入或移动到目标名后，记录事件流水及有效
  文件版本；版本按 SHA256 去重存放，旧版本保留。
- 主线/章节/生存存档变化后等待 750 ms，再核对并复制整组 Documents。捕获前后以及复制后
  再验证哈希、成员与 SBIN 容器；变化中或损坏的数据重试，最多 8 次、间隔 600 ms。
- 另有 7 秒轮询兜底。设置、Core 或共享文件单独变化可进入版本流水，避免将音量等设置变化
  当作新剧情节点；整组归档仍包含所有普通依赖、隐藏文件和空目录。
- 保存关卡 ID、活动槽、存档位置、资源摘要、时间、轮次、标签及采集原因。原始 SBIN 字节
  完整保存，元数据无法解读时留存错误信息。
- 节点目录使用 `deadspace.cold-profile.v1` 清单，现有校验和冷恢复工具可以直接读取。
- 可选 PixelCopy 画面最长边 960 px，输出 JPEG。图片属于落盘后的观察画面，可能晚于实际
  保存时刻；失败不会丢弃节点，`screenshot.json` 记录状态。
- 库预算 1 GiB，预留约 64 MiB 可用空间。达到预算/存储不足时暂缓新增，不自动删除旧节点。
  状态显示节点数、版本数、最近关卡和错误；初始化失败会记录并提示。
- 已发布节点保持独立；进程中断留下的未完成目录不作为有效节点，截断的事件行保留为
  `events-interrupted-*` 后再恢复流水写入。

文件事件可能被合并，短间隔覆盖、进程终止和设备状态可能影响捕获。这是文件观察与稳定复制，
尚未接入引擎原生写档事务钩子，**不能宣称逐写 100% 不漏**。事件计数、原始版本、失败与
未完成记录用于核对覆盖；“已采集”也不代表该节点已逐一加载验收。

## 代码入口

- `SaveNodeArchive.java`：与 Android UI 无关的完整归档、哈希、版本、流水、去重与导出核心。
- `SaveNodeMetadata.java`：只读 SBIN 节点摘要，保留原始完整文件。
- `SaveNodeMonitor.java`：FileObserver、重试与轮询、退出收尾、可选截图回调。
- `MainActivity.java`：仅显式启用时启动监控；暂停标记、画面采集。
- `LauncherActivity.java`：默认关闭的主开关、轮次、图片选项、状态与导出。
- `tools/save-lab/node_bank.py`：导出库的完整性检查与编辑器索引；损坏、未知编码、流水缺口和
  未完成节点分别报告，始终不把一周目覆盖率标成已验收。

节点库 ZIP 解压后可运行：

```powershell
python tools/save-lab/save_lab.py node-bank-inspect C:/SaveTest/save-node-bank --out C:/SaveTest/node-index.json
```

每个有效节点位于 `nodes/<节点名>/`，可直接用已有 `profile-verify` 校验，或在之后明确选择
节点时通过 `adb-activate` 冷恢复；索引读取不会自动激活存档。
