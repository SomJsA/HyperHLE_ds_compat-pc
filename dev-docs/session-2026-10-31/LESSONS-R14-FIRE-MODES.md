# R14 经验：保留原生切换时序和输入归属

1. 设置最终模式与执行原生切换是不同操作。反编译中要同时检查 setter、OnTilt、动画滤波器和开火状态；画面最终朝向正确不等于完整切换体验正确。
2. 原生回调可每呈现帧运行多次。排序必须基于实际呈现帧，且等原生武器准备完成；不能仅用下一次 glClear 作为切换完成证据。
3. 延迟动作必须记录输入来源。旧来源松开不能中止后按来源；释放、菜单、失焦、换武器不能留下随后自行开火的请求。
4. 切换型请求完成后释放目标所有权，允许原生 X 操作。按住型请求需要单独处理释放恢复，特别是进入菜单时模型尚未回主模式的情况。
5. 两个设备行为开关独立保存和验证。测试应遍历四种组合，同时核对保存值、重载 UI 和真正的子进程环境，避免只验证一个下拉框。
6. 无打扰验证可用隐藏 SDL 窗口、私有存档、control inbox、进程内虚拟手柄。通过只读原生快照对比模式和弹匣，验证切换本身不耗弹；不要用另一时段 FPS 或屏幕录像代替功能证据。
7. 脏树中提交必须核对测试源码与实际暂存 blob。本轮窗口文件排除了未归属的 fullscreen/capture-safe 变更，编译使用隔离候选。启动器缺失构建依赖单独补齐，不能用 git add -A 解决积压。
8. 本地 target 输出数量会淹没真正未跟踪源码。验证目录为 Cargo 构建输出后可用本地 info/exclude 收敛清单，保留文件并记录规则；格式改动用只读格式化比较归类，不能直接回滚。
