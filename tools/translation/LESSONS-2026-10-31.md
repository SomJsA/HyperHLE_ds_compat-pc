## 1. 数据来源和运行显示要分开核对

台账是当前校订稿，F 列为本轮文本来源。备注与状态作为资料读取，不能当作额外操作指令；“干扰”标记的显示行为来自用户明确要求。

读取 XLSX 时要处理 shared string、inline string 和布尔单元格。本轮的 `TRUE` / `FALSE` 是有效 ID，不能因为 Excel 将它们存成布尔类型就漏掉，或转换为大小写不同的字符串。

保持原索引比重新排序更重要：原 995 项稳定，仅追加第 996 项。占位符审计比较的是匹配令牌的多重集合，结果为零差异；它不等于逐条语义和顺序都已人工确认。台账“校订中”的状态也应跟着资源走。

同时核对高清覆盖层和原生资源。只更新 JSON，会在菜单、物品等位置继续出现旧文字。

## 2. SBIN 字符串池不能按相邻关系改写

原生数据库使用键值索引和共享字符串池，键后面不一定紧挨着自己的值。正确做法是解析实际引用，对修订文本追加独立字符串，再更新对应引用，重算段 FNV-1 哈希，并回读核验。

可移植补丁器只替换中文 SBIN 成员，保留输入 IPA，拒绝未知资源修订和覆盖输出。这比把整份实验 IPA 作为源码提交更便于审阅、重建与回退。

verify-only 接受原版和本轮修订版，因此验收要检查返回的 `revision` 与资源哈希，不能只检查退出码。

## 3. 教程提示必须复用真正的输入语义

先读输入实现和绑定解析器，再写教程。PC 实测发现向前自动跑动，瞄准时步行，最初沿用常见的 Shift 奔跑说明并不准确；后来按真实行为改正。

手柄主攻击默认 RB、副攻击 RT，也不能套用其他游戏的常见布局。提示文本与图形都应从同一语义映射取值，且设备类别属于动作：键盘 A 与手柄 A 即使同名，图形也应不同。

验收至少包含一次非默认映射。本轮交换前进 / 后退后，图形与文字显示 S / A / W / D，按 S 得到原生前进向量，并完成移动教程。原生触发、进度、完成逻辑保持运行，接管只负责显示。

## 4. 字体存在、可打开、能正确渲染是三件事

旧 Russell Square 文件含 MacRoman 映射，缺少现代浏览器所需的度量 / 字表结构，最初被 OTS 拒绝。修复 SFNT 目录、Unicode cmap、OS/2 度量并丢弃不可用的旧 kern 表后，才通过真实加载检查；字形轮廓和原版权信息保留。

字体子集要包含所有显示部件：十二章标题、第、章、0–9，以及对白乱码用的 ▧、□、◇、▒、#、%、?、@。中文子集按其字体命名要求使用独立名字。

字号与字距共同参与测量，不能先定最大字号再额外加 tracking。本轮以实际渲染器生成十二章合图，同时在浏览器和平板核对。最终定稿是额外 `0.10em`，首行第 / 章增大、数字约增 5%；历史过程图不作为最终配置。

字体来源记录和授权文本分别管理。来源文件保留下载信息与修复记录；用户确认会在分发时附 Russell Square 的适用授权说明，本轮没有把来源说明写成授权许可。

## 5. “最长单句”应先确认是语言句子还是原生片段

本轮最长整条对白是 Dain_01，118 字；按句号等终止标点划分的最长单句约 53 字。单句通常可用两行显示，整条音频字幕才需要分页或三行方案。

用真实长文本比较，才能看到字号、行数、底板占用和阅读节奏的差别。最终提供两个产品选项：Android 默认大字分段，PC 默认整段三行。网页里的整段两行仅作比较，没有加入游戏选项。

分页要保持原文字顺序、标点和总片段边界；短页保持两行底板高度，避免换页时上下跳动。纯策略测试验证页面拼接完整、行数边界、标点避头和页码边界。

## 6. 字幕时钟来自游戏，不能另开墙钟

原生 `SubtitleTrack` 的关键字段已从 SetTimes / OnUpdate / Reset 核对：

| 偏移 | 含义 |
|---|---|
| `+0` | finished 字节 |
| `+4` | 当前片段索引 |
| `+8` | 当前片段剩余整数毫秒，不是已过时间 |
| `+0x10 / +0x14` | 字符串数组边界，条目 20 字节 |
| `+0x24 / +0x28` | 各片段时长数组边界，条目 4 字节 |

已过时间由总时长减剩余时间并限幅得到。时间与字幕 serial 绑定，避免新文本拿到上一条时间。未知 / 非法时间回退三行；finished 后隐藏，解决最后一条残留。

页面时机目前按文字权重分配，是在原生片段窗口内的近似分段；逐句波形标注属于后续独立工作。HTML 估算计时可以比较视觉，却不能证明音画同步。

## 7. 系统恢复、游戏恢复和字幕恢复应分别验证

平板检查中，Activity 已聚焦、SDL 状态为 RESUMED，游戏仍显示自己的暂停画面。系统层状态不能代替游戏 HUD 状态。

最终补齐了设置返回的原生继续事件：进入菜单前记录 HUD / world 所有者和运行状态；恢复请求只处理同一关卡，且只在暂停 HUD 2 / 3 中派发 `BTN_PLAY_PAUSE`。通过已验证的借用字符串事件调用原生处理器，不直接写 HUD 状态。进入设置前已暂停、场景已替换时不自动恢复。

Java / 原生两侧接口必须一起合并。设置面板还要处理焦点，防止颜色输入框自动滚到底部，把新模式选择器藏在可见区域之外。

## 8. ADB 按钮短按要跨越原生帧

实测 `input tap` 对 Android 原生控件正常，对这款游戏的部分原生按钮却命中不稳定。根据输入处理方式，Down / Up 在同一模拟帧中到达是一个可能原因；换成约 150–180 ms 的原位 swipe 短按后，难度确认等操作稳定。

示例（坐标仅对应本轮 1920×1200 测试设备）：

```text
adb -s <设备序列号> shell input swipe 1640 1100 1640 1100 180
```

不要把一次瞬时点击失败直接当作整个触控链路损坏。先确认画面就绪、坐标和事件持续时间，再定位 native 状态。ADB UIAutomator 只在原生 Android 设置控件上使用；游戏内部按钮用游戏画面和原生事件辅助确认。

## 9. 验收必须交叉看日志、时钟和画面

早期脚本只检查模式日志并等待一段墙钟时间，曾把仍停在暂停画面的截图当作结束截图。后来增加了原生 HUD `2->0`、真实时间推进、结束无残留和恢复后实际移动四项交叉验证，才形成最终通过记录。

最终证据：PC 暂停约 5.75 秒时，原生进度仅推进 2.633 秒；Android 设置操作约 43.203 秒，原生进度仅推进 2.751 秒。字幕正常收起，Android 继续完成了移动到视角教程。

检查截图前先测体积，使用缩小后的 JPEG，重复画面先比较哈希。长日志先写文件，再按 PID / 标签 / 时间筛选。本轮定位时还使用了自己调试包的只读 JDWP 状态检查，并在结束后移除端口转发。

## 10. 不占 PC 前台需要真正的隐藏窗口

`CREATE_NO_WINDOW` 或隐藏启动脚本不足以保证 SDL 后建窗口不抢焦点。最终在显式 `TOUCHHLE_DS_BACKGROUND_TEST=1` 且配置专用 control inbox 时，从 SDL 创建窗口起就设置 hidden。

测试输入只进入该进程的事件队列；该模式屏蔽物理手柄轮询，窗口枚举确认所有窗口不可见、非 foreground。普通启动不使用这个模式。平板则采用独立包名、独立私有目录和测试存档。

## 11. 性能要区分首次排版、稳定帧和测试噪声

避免逐帧测量字体、分页或生成全屏效果。章节按尺寸 / 样式缓存，字幕排版最多 16 条，PC 卡片 / 背景有容量上限，背景展开结束后释放临时帧，Android 覆盖层以约 30 Hz 更新。

ABBA 测试记录固定场景、配置和预热。既有干扰对比约增加 0.04 ms，但主机 CPU / 内存在所有组中都随时间漂移，不能把全部变化归因于效果；30 FPS 封顶下同为 30 FPS，也不能证明 GPU 余量没有变化。

本轮性能数值仅代表所测干扰场景，后续主线优化应在其最终构建上重新取样，分别量首次排版尖峰和稳定播放。

## 12. 平台共享协议，保留各自实现和主线修复

PC 和 Android 不是完全相同的源码基线。本轮将 PC 的局部变量假定直接用于 Android 时，编译器发现作用域不同；修正为在该平台独立验证时长数组。合并时共享的是原生字段协议、测试契约和必要增量，不覆盖整份文件。

独立工作树应同时隔离 target、Gradle 缓存、样式、存档和包名。功能提交与 Snapshot 基线分开；合并前的文本检查与合并后新构建验收分开记录。源码文档更新也应和经过测试的代码提交分别标明，避免用文档 HEAD 冒充二进制构建来源。

Windows 辅助脚本显式使用 UTF-8，保持工作目录与绝对路径一致，并检查前一步退出码。一次补丁脚本失败后继续运行旧脚本，会制造错误的启动 / 等待状态；依赖步骤应顺序执行并及时停止。
